# Documentation Authority

The canonical map is intentionally small:

| Need | Current authority |
| --- | --- |
| Product promise, non-goals, supported commands, state ownership | `docs/PRODUCT_CONTRACT.md` |
| Machine-readable release contract | `premode.product.json` |
| Installation and getting started | `docs/FIRST_RUN.md` |
| Codex integration | `AI_START_HERE.md`, then `docs/PCODEX_BOOTSTRAP.md`; `docs/PCODEX_MCP_STATUS.md` is advanced alpha-era evidence |
| OpenClaw status | `docs/PRODUCT_CONTRACT.md`; other OpenClaw documents are advanced/research evidence |
| Troubleshooting and tester reports | `docs/PRIVATE_BETA_TESTER_PACKET.md` |
| Claims and limitations | `docs/CLAIMS_AND_LIMITATIONS.md` |
| Version and release process | `docs/RELEASE_AUTHORITY.md` |

`README.md`, `AI_START_HERE.md`, `premode.ai.json`, and `AGENTS.md` are entrypoints, not competing product contracts. Documents under `docs/history/` are historical. Files named for V2/V3/V4, private alpha, old patch plans, lab IDs, machine-specific paths, or benchmark snapshots are noncanonical unless a current authority explicitly links them for evidence.

The desired filenames `docs/GETTING_STARTED.md`, `docs/CODEX_INTEGRATION.md`, `docs/OPENCLAW_INTEGRATION.md`, and `docs/TROUBLESHOOTING.md` do not yet exist. Creating full guides would overstate incomplete consolidation; the table above maps each role to verified current documents until a documentation-only migration is approved.
